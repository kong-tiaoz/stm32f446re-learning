# 本地教材带读约定

- 每个实验工程维护根目录的 `本代码所用API说明.md`，按 ../../docs/API说明模板.md 的六问卡逐项说明；新增/删除 API 或改变参数含义时同步更新，工程 README 必须提供入口。后续默认 CubeMX + HAL，寄存器基线仅保留历史参考。

- 用户英语略高于六级，已会 STM32 基础外设，偏好先运行完整例程，再拆解代码并动手修改。
- 2026-10-30 最新偏好：当前重心是借助 AI 快速跑通、熟悉 VS Code 操作环境。英文仅处理必要术语；代码在书本指导下理解入口、改动点和基本编译流程，暂不要求彻底理解实现。
- 2026-10-31 起按 function-modules.md 的功能模块和验收成果推进，最终作品为可配置的数据采集仪；取消固定周数及每节时间配额，不将英文精读作为必经门槛。以 Mastering STM32 第二版为主线，野火 F4 HAL 教程按需作为移植参考。
- 收到“继续上一课”时，先读本目录 README、function-modules.md、notes/progress.md 及对应项目的 artifacts/verification.md，按实际未完成项继续。当前下一模块为已有 book-debugging 的串口交互与基础调试，不能因为材料已准备而标记为已验收。
- 每次围绕一个操作任务定位原书小节；解释本次操作涉及的少量代码与必要术语。用户需要时再展开英文难句或深入实现。区分原书表述、助手纠正和自拟例句。
- 原文中的 CubeIDE 菜单应映射到当前 VS Code 工程；不能把旧版截图当作当前界面，也不能把 CubeIDE .launch 当成 VS Code launch.json。
- 先引导运行已准备例程，再给小修改。记录用户实际结果，不把准备材料或助手做过的修改写成用户已经完成的练习。
- 更新进度时保留证据；实体 LED 现象、RESET、断电重启须有用户观察或真实测量，不能由编译成功推断。
- 个人学习状态同步更新到 notes/progress.md；.local/ 只保存内部执行记录。整个型号目录已使用同一个公开 Git 仓库，教材正文与配图、Flash 备份、完整日志不上传；公开验收摘要不含设备序列号。
- 原文与源码各自保留来源。转换章节中的代码是阅读材料，编译基准为独立工程；不会自动把整本书发给聊天。
- 用户要求讲解时集中讲解；按用户明确指令执行构建、烧录或修改，沿用项目的完整备份与目标校验脚本。
- 每个模块按“先运行完整例程 → AI 最小修改并检查差异 → 编译与硬件验证 → 按需理解和复盘”推进；先完成无操作系统版本，再用 FreeRTOS 重构。新增实验保持型号总目录下的独立工程，硬件到对应模块开始时再核对。
- Git 提交由用户操作，助手提供各项变更说明；“调整学习计划”不授权修改工程、连接或烧录硬件。保留 100/900 ms 闪灯的历史验收，后来的 100/2000 ms 源码另行验证，不用新时序覆盖旧证据。

- 每张 API 六问卡下必须附“本工程源码示例”：从当前工程摘录真实调用及必要上下文，标明相对源码路径、函数或行号，保留实际参数；简单、模板化接口通常保留 1 个代表性示例，最多 2 个有明显用途或参数差异的示例；相同调用和重叠片段不重复罗列，不穷举所有调用位置，错误路径和未调用模板明确标注。源码变化时同步更新片段和位置，不用虚构的通用示例代替。
