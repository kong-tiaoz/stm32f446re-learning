# 本代码所用 API 说明：统一模板与维护规则

适用：本型号目录中自行维护的实验工程。每个工程根目录固定保存 `本代码所用API说明.md`，工程 README 链接到该文件。后续默认使用 CubeMX + HAL，寄存器测试仅作历史参考，不作为必修前置。

## 统计范围

- 写明项目、入口、源码版本/核对日期、统计涉及哪些源文件。
- 外部函数、HAL 功能宏、CMSIS 接口按名称去重，分类计数；同名多次调用只算一种。
- 只统计应用、MSP、中断和项目适配层直接引用的外部接口，不递归展开厂商库和 C 库内部调用。不把常量、类型和函数定义误算为调用。
- 正常路径、错误路径、仅模板保留/当前未调用分别标注。项目封装、回调、中断及运行库入口另列，不混入外部 API 总数。
- 每个外部 API 单独填写下面六问，不用一句“由模板生成”替代说明。宏标注为宏；返回值依据当前源码，不假定 void 接口可判断成功。

## API 名称：`接口名称()`

源码位置：文件、函数或行号。路径状态：正常 / 错误 / 模板未调用。

| 问题 | 答案 |
| --- | --- |
| 谁提供？ | 厂商/标准库/项目模块，必要时给出头文件 |
| 做什么？ | 本项目实际用来完成的行为 |
| 输入什么？ | 参数类型、实际参数与单位、缓冲区/指针要求 |
| 返回什么？ | 类型、成功/失败含义；void 或宏需明确 |
| 调用前准备什么？ | 时钟、引脚、初始化、上下文及资源条件 |
| 调用后验证什么？ | 返回值、状态、串口、断点或硬件现象；没有验证就写待验证 |

## 更新与验收

添加、删除调用或改变参数含义时，同步更新 API 卡和统计数量；调用仍相同但时序变化也须更新项目实际参数。说明与源码一起由用户提交，助手提供变更摘要。源码用途说明与硬件验收分开，历史验证结果保留版本边界，不能把模板存在或编译通过写成运行已通过。

参考：[HAL 闪灯工程](../book-hello-nucleo/本代码所用API说明.md)、[串口调试工程](../book-debugging/本代码所用API说明.md)。

每张 API 六问卡下必须附“本工程源码示例”：从当前工程摘录真实调用及必要上下文，标明相对源码路径、函数或行号，保留实际参数；多处调用的关键差异应覆盖，错误路径和未调用模板明确标注。源码变化时同步更新片段和位置，不用虚构的通用示例代替。
